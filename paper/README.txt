WHAT IS IN THIS PACKAGE
-----------------------
  main.tex          Source. Elsevier's elsarticle class, [3p] single
                    column at journal density.
  main.pdf          The compiled manuscript.
  numbers.tex       EVERY number quoted in the paper, as macros,
                    generated from ../results/*.json. Not hand-edited.
  refs.bib          Bibliography, 30 entries, all cited.
  main.bbl          Pre-built bibliography. Editorial Manager wants
                    this alongside the .tex.
  declarations.tex  CRediT, competing interest, data availability,
                    funding. Inputted at the end of main.tex.
  highlights.tex    Elsevier Highlights, uploaded as a separate file
  highlights.pdf    at submission. Five bullets, each under 85 chars.
  figs/             All figures (PDF), generated by make_figs.py.
  make_numbers.py   Generates numbers.tex from the result files.
  make_figs.py      Generates figs/*.pdf from the result files.
  tools/            check_manuscript.py -- pre-submission hygiene.
  Makefile          Build targets, see below.
  cover_letter.md   Draft cover letter to the editor.

TO REBUILD
----------
  make              # main.pdf
  make highlights   # highlights.pdf
  make numbers      # regenerate numbers.tex + figures, then rebuild
  make gate         # THE SUBMISSION GATE (see below)
  make check        # gate + abstract length, highlights, build hygiene
  make package      # flat submission/ folder for Editorial Manager

`make package` matters: Elsevier's LaTeX instructions require every
submission file -- .tex, .bbl, .bib, and all figures -- to sit at the
same folder level, with no subfolders. This repository keeps figures in
figs/, so the target flattens a copy into submission/ and then rebuilds
it there to prove the flattened copy still compiles. It also prints the
Editorial Manager item type for each file. Do not upload LaTeX files as
Supplemental items.

Requires a TeX distribution with elsarticle, lmodern, booktabs,
multirow, microtype and xurl. TeX Live 2021 or later is sufficient;
everything used here ships with a full install.

THE SUBMISSION GATE -- READ THIS BEFORE SUBMITTING
--------------------------------------------------
No number in this paper is typed by hand. Every one is a macro in
numbers.tex, generated by make_numbers.py from the committed result
JSONs. A configuration that has not been run yet expands to \PENDING,
which renders as a red [PENDING RUN] marker in the PDF.

  make gate     # names every unresolved number the paper quotes
  make check    # the same, grouped by the lane that resolves it

exits non-zero while any number the manuscript quotes is still
unresolved. NOTHING CARRYING A [PENDING RUN] MARKER MAY GO TO A VENUE.

Note what the gate does and does not require. make_numbers.py emits a
full grid per family -- 683 macros -- but main.tex quotes only 151 of
them. The gate is on the quoted subset, because that is what decides
whether a marker reaches the page; the campaign does not have to run to
completion for the paper to be submittable, only far enough to resolve
the numbers the paper actually cites. Both counts are printed, so the
difference is visible rather than assumed.

As of this writing the gate does not pass: 33 quoted macros are
unresolved (plus 13 literal \PENDING hedges in the prose, each carrying
a "% RETIRES WITH:" comment naming its lane). The campaign in
../run_remediation.sh is running. Launch or resume it with:

  cd .. && setsid nohup systemd-inhibit \
    --what=sleep:idle:handle-lid-switch --why="FL remediation campaign" \
    --mode=block env DEVICE=cuda bash run_remediation.sh \
    >/dev/null 2>&1 & disown
  tail -f ../results/remediation.log

It is resumable -- run_sweep skips any cell whose JSON already exists.
Run `make numbers` after each lane completes. Two figures
(fig_dose, fig_evasion) and their captions upgrade themselves from
placeholder to final via \IfFileExists the moment make_figs.py can draw
them, so there is no manual swap to forget.

Note: the machine is a laptop. Every interrupted run so far died to a
suspend mid-cell, not to ollama. Run on mains, under the inhibitor
above.

TWO-COLUMN LAYOUT
-----------------
JISA typesets in two columns in print. To match that look, change the
class line in main.tex to

  \documentclass[final,5p,times,twocolumn]{elsarticle}

This was tested and it does compile -- 12 pages, exit 0. But three
tables then overflow the column and must be promoted to table* wide
floats first:

  tab:main       headline comparison, 9 columns  (158pt over)
  tab:adaptive   static vs adaptive attacker     (153pt over)
  tab:magnitude  magnitude / order-statistic     ( 75pt over)

The figure widths also need to go back to \columnwidth, and the three
width constants at the top of make_figs.py (W_COL, W_WIDE, W_PAIR) need
retuning to the narrower column -- they are currently derived from the
6.5 in single-column \textwidth, and the \includegraphics fractions in
main.tex are matched to them so that no figure is rescaled.

Single column [3p] is the default here because all nine tables fit it
without wide floats and reviewers read it more easily. Elsevier permits
either.
